## 开头：不是按次数计费，是按处理量计费

AI API 不像视频网站会员"每月 30 元无限看"，也不是"每次对话 0.5 元"。它按实际处理的 Token 数量计费——一次短问答可能只花 0.01 元，一次上传长文档要求详细分析的请求可能花 2-3 元。

**核心差异**：
- ❌ 不是"我问了 10 次，花了多少钱"
- ✅ 而是"我输入了 5000 个 Token，输出了 2000 个 Token，花了多少钱"

本文带你看懂 Token 计费、输入输出单价、上下文累积成本，以及如何在充值前估算你的实际花费。

**适用人群**：
- 第一次看到"每百万 Token"的价格表，不知道怎么换算成实际费用
- 发现对话越聊越贵，不知道为什么
- 想在充值前估算每月预算

## 准备工作

### 你需要了解的基本概念

**Token 是什么**：
- Token 是模型处理文本的最小单位
- 中文：1 个 Token ≈ 1.5-2 个汉字
- 英文：1 个 Token ≈ 0.75 个单词（4 个字母）

**快速估算公式**：
- 中文文本：字数 ÷ 1.5 ≈ Token 数
- 英文文本：单词数 ÷ 0.75 ≈ Token 数

**示例**：
```
"你好，今天天气怎么样？" = 12 个汉字 ≈ 8 个 Token
"Hello, how are you today?" = 5 个单词 ≈ 6-7 个 Token
```

### 需要准备的工具

1. **服务商的价格表**
   - 找到你的服务商后台 → "价格"或"Pricing"页面
   - 记录你常用模型的输入、输出单价

2. **Token 计数器**（可选）
   - OpenAI Tokenizer: https://platform.openai.com/tokenizer
   - 本地客户端（Chatbox/Cherry Studio）通常会显示 Token 数

3. **计算器或 Excel**
   - 用于计算实际费用

## 详细步骤

### 第 1 步：看懂价格表的三个关键数字

**操作**：
打开你的服务商价格表，找到你要使用的模型（如 gpt-3.5-turbo）。

**填写**（以 OpenOx 2026-08-14 价格为例）：

| 模型 | 输入价格 | 输出价格 | 倍率 |
|------|---------|---------|------|
| gpt-3.5-turbo | $0.50/M tokens | $1.50/M tokens | 1.0x |
| gpt-4 | $30/M tokens | $60/M tokens | 1.0x |
| claude-3-sonnet | $3/M tokens | $15/M tokens | 1.0x |

**解读**：
- **M tokens** = 百万（Million）Token = 1,000,000 Token
- **输入价格** = Input Price = 你发送给 AI 的内容成本
- **输出价格** = Output Price = AI 生成的内容成本
- **倍率** = 中转站额外收费系数（1.0x = 官方价格，1.2x = 贵 20%）

**验证**：
确认以下几点：
- ✅ 输入和输出价格是分开列出的（不是同一个数字）
- ✅ 价格单位是"每百万 Token"（/M tokens 或 /1M tokens）
- ✅ 倍率通常在 1.0x - 1.5x 之间（超过 2.0x 需谨慎）

**结果**：
你现在知道了三个关键数字，可以用于下一步的成本计算。

### 第 2 步：计算单次对话成本

**操作**：
用以下公式计算一次真实对话的费用。

**填写**（示例场景）：
假设你问了一个问题，AI 给出了回答：

```
你的问题（输入）：
"请帮我总结以下文章的三个要点：[300 字的文章内容]"

AI 的回答（输出）：
"1. 要点一...\n2. 要点二...\n3. 要点三...\n总计约 200 字"
```

**Token 估算**：
- 输入：50 字问题 + 300 字文章 = 350 字 ÷ 1.5 ≈ **233 tokens**
- 输出：200 字回答 ÷ 1.5 ≈ **133 tokens**

**费用计算**（使用 gpt-3.5-turbo）：
```
输入成本 = 233 tokens × ($0.50 / 1,000,000) = $0.0001165 ≈ ¥0.0008
输出成本 = 133 tokens × ($1.50 / 1,000,000) = $0.0001995 ≈ ¥0.0014
总成本 = ¥0.0008 + ¥0.0014 = ¥0.0022（约 0.2 分）
```

**验证**：
发送这个真实对话后，检查服务商后台账单：
- ✅ 费用应该在 0.002-0.003 元之间
- ✅ 账单详情应该显示输入和输出的 Token 数
- ✅ 如果实际费用高出 10 倍，可能存在倍率或多次重试

**结果**：
你现在会计算单次对话的理论成本，并能与实际账单对比验证。

### 第 3 步：理解上下文累积成本

**操作**：
进行一次多轮对话测试，观察成本变化。

**填写**（5 轮对话示例）：

| 轮次 | 你的输入 | 实际发送的内容（包含历史） | 输入 Token |
|------|---------|-------------------------|-----------|
| 第 1 轮 | "你好"（2字） | "你好" | ~2 tokens |
| 第 2 轮 | "今天天气"（4字） | "你好" + AI回复(10字) + "今天天气" | ~13 tokens |
| 第 3 轮 | "谢谢"（2字） | 前2轮内容(~30字) + "谢谢" | ~22 tokens |
| 第 4 轮 | "再见"（2字） | 前3轮内容(~50字) + "再见" | ~35 tokens |
| 第 5 轮 | "拜拜"（2字） | 前4轮内容(~70字) + "拜拜" | ~50 tokens |

**关键发现**：
- ❌ 你以为每轮只输入 2-4 个字
- ✅ 实际上每轮都在重新发送之前的所有内容
- 📈 输入 Token 数随对话轮次线性增长

**费用对比**：
```
第 1 轮成本：约 ¥0.0001
第 2 轮成本：约 ¥0.0005（是第 1 轮的 5 倍）
第 3 轮成本：约 ¥0.0010（是第 1 轮的 10 倍）
...
```

**验证**：
在客户端（Chatbox/Cherry Studio）中：
- ✅ 打开开发者工具 → Network 面板
- ✅ 发送一次对话，查看请求的 `messages` 字段
- ✅ 确认是否包含了之前的所有对话历史

**结果**：
你理解了为什么"对话越聊越贵"——不是 AI 变贵了，而是每次都在重复发送历史内容。

> 🖼️ **需要补充截图**：浏览器 Network 面板，显示包含历史消息的请求体

### 第 4 步：识别隐藏成本项

**操作**：

**填写**（常见隐藏成本检查表）：

| 收费项 | 是否收费 | 价格 | 说明 |

**验证**：
1. 打开服务商文档 → 搜索"pricing"或"计费"
2. 查找是否提到"image input"、"search"、"cache"

### 第 5 步：估算每月预算

**操作**：
根据真实使用场景估算每月花费。

**填写**（个人使用场景示例）：

| 场景 | 频率 | 单次 Token | 单次成本 | 月成本 |
|------|------|-----------|---------|--------|
| 日常问答 | 每天 20 次 | 输入 50 + 输出 100 | ¥0.003 | ¥1.8 |
| 长文总结 | 每周 5 次 | 输入 2000 + 输出 500 | ¥0.05 | ¥1.0 |
| 代码调试 | 每周 10 次 | 输入 500 + 输出 800 | ¥0.02 | ¥0.8 |
| **总计** | - | - | - | **¥3.6/月** |

**验证**（5 天测试法）：
1. 连续 5 天正常使用 API
2. 记录每天的实际花费
3. 计算平均值：`(5天总费用 / 5) × 30 = 月度预算`

**示例**：
```
第 1 天：¥0.15
第 2 天：¥0.22
第 3 天：¥0.18
第 4 天：¥0.30（处理了一个大文档）
第 5 天：¥0.12
---
平均：¥0.194/天
月度预算：¥0.194 × 30 ≈ ¥5.8
```

**结果**：
你得到了一个基于真实使用的月度预算，可以决定首次充值金额。

**充值建议**：
- 测试阶段：充值 5-10 元（够用 1-2 个月）
- 日常使用：充值 20-50 元（够用 3-6 个月）
- 重度使用：充值 100 元（按需补充）

- Claude 3 系列支持 Prompt Caching
- 重复发送相同内容时，成本降低 90%

## 常见错误

### 错误 1：只看单价，不看实际消耗

**错误认识**：
"gpt-3.5-turbo 只要 $0.50/M tokens，很便宜！"

**真实情况**：
- 如果你每次都发送 5000 字的上下文
- 一次对话可能消耗 10,000 tokens
- 实际成本：10,000 × ($0.50/1,000,000) = $0.005 ≈ ¥0.035
- 一天 20 次 = ¥0.7/天 = ¥21/月

**教训**：
单价低不代表总价低，关键看你的实际使用量。

---

### 错误 2：忽略失败请求的扣费

**错误认识**：
"请求失败了，应该不会扣费吧？"

**真实情况**：
- 大部分服务商会对失败请求收费
- 即使 AI 返回了错误信息，输入 Token 也已被处理
- 频繁失败会浪费大量费用

**示例**：
```
你发送了一个 5000 tokens 的请求
AI 返回：Error: Context length exceeded
结果：照样扣费 $0.0025
```

**解决方法**：
- 先用小文本测试配置是否正确
- 确认无误后再处理大文档
- 设置每个密钥的额度上限（如 10 元）

---

### 错误 3：被"倍率"误导

**错误认识**：
"中转站 A 是 1.0x 倍率，中转站 B 是 1.2x 倍率，A 肯定便宜。"

**真实情况**：
- 倍率只是基础价格的系数
- 还要考虑充值汇率、活动折扣、赠送额度

**对比示例**：

| 服务商 | 倍率 | 充值汇率 | 实际价格 |
|--------|------|---------|---------|
| OpenOx | 1.0x | ¥1 = $0.15 | gpt-4: ¥200/M tokens |
| UU API | 1.2x | ¥1 = $0.18 | gpt-4: ¥200/M tokens |
| APINebula | 0.8x | ¥1 = $0.12 | gpt-4: ¥200/M tokens |

**结论**：
三家实际价格相同，不能只看倍率。

**正确方法**：
用真实场景测试，看账单扣费，而不是算纸面价格。

---

### 错误 4：不设置预算提醒

**错误认识**：
"我用不了多少，不用设置预算。"

**真实情况**：
- API 密钥泄露，一夜被盗刷几千元
- 忘记关闭测试脚本，持续消耗余额
- 误操作上传了几十份大文档

**建议**：
1. 为每个密钥设置额度上限（如 10 元）
2. 开启余额提醒（低于 5 元时通知）
3. 定期（每周）检查账单明细

## 安全提醒

### 预算控制

⚠️ **必须设置的三道防线**：

**第 1 道：密钥额度限制**
- 为每个密钥设置最高额度（如 10 元）
- 超过自动停用，避免无限制消耗

**第 2 道：余额提醒**
- 开启邮件或短信提醒
- 余额低于 5 元时通知

**第 3 道：定期审计**
- 每周查看账单明细
- 检查是否有异常消耗

### 密钥安全

❌ **不要做**：
- 在公开代码仓库中提交密钥
- 在客户端日志中打印完整密钥
- 将高额度密钥给不熟悉的人使用

✅ **应该做**：
- 为不同用途创建独立密钥（测试、生产、共享）
- 为每个密钥设置不同的额度限制
- 不用的密钥及时撤销
