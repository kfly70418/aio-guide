## 开头

挑选 AI API 中转站主要看 7 点：运营主体透明度、模型真实性、价格透明度、稳定性记录、安全措施、售后响应和退出机制。本文基于 2026 年 8 月对 12 家主流中转站的实测，给出可重复验证的检查流程。不要只看折扣力度，信息不透明的平台遇到问题时往往找不到人。

## 准备工作

开始筛选前，你需要：

**材料清单**：
- 3-5 家候选平台的官网链接（可从本站排行榜选择）
- 小额测试预算：每家 5-10 元，测试 3 家约 30 元
- 一个常用的测试问题（例如："用 100 字解释量子计算"）
- Excel 或表格工具，记录各平台的检查结果

**预计时间**：
- 单个平台完整检查：15-20 分钟
- 3 家平台对比：1 小时
- 小额测试周期：3-7 天

**安全提醒**：
- 测试阶段不要充值超过 50 元
- 不要在测试期间发送敏感信息
- 使用独立密码，不要与主要账号相同

## 详细检查步骤

### 第 1 步：信息透明度检查

**操作**：
1. 打开候选平台官网首页
2. 滚动到页面底部，查找"关于我们""服务条款""隐私政策"链接
3. 依次点击并查看内容完整性
4. 在价格页面查找计费规则说明

**验证标准**：

✅ **好的信号**：
- 明确的公司名称或个人运营主体
- 完整的服务条款（更新时间在 3 个月内）
- 清晰的计费规则：输入/输出倍率、汇率、退款政策
- 多种联系方式：邮箱、工单系统、Telegram 群组

⚠️ **风险信号**：
- 没有关于页面，或只有"我们致力于提供优质服务"等空话
- 服务条款明显是模板套用，没有具体计费细节
- 只有 Telegram 群组联系方式，没有邮箱或工单系统
- 价格页面只标注折扣力度，不说明上游来源和倍率

**实测案例**（2026-08-12）：
- API Xuan：有完整主体信息、服务条款和详细计费规则 ✅
- [平台 B]：只有 Telegram 群组，无其他联系方式 ⚠️
- [平台 C]：服务条款使用通用模板，未提及具体业务 ⚠️

![信息透明度检查示例：服务条款与联系方式对比](../images/articles/choose-01-transparency-check.png)

### 第 2 步：模型真实性验证

**操作**：
1. 在平台模型列表中查看是否标注准确的 Model ID（如 `claude-opus-5`）
2. 查看是否有版本说明和功能差异对比
3. 充值小额（5-10 元）后进行实际测试
4. 用自己熟悉的测试问题对比输出质量

**验证方法**：

不要依赖单次回答判断模型身份，使用以下测试组合：

**测试 1：上下文能力测试**
- 输入一段 5000 字的文本，要求总结
- 验证模型是否能准确引用文中细节
- 记录响应时间和准确度

**测试 2：功能支持测试**
- 如果平台声称支持 Claude Opus 5，测试其思考（thinking）功能
- 如果声称支持 GPT-4o，测试其图像理解能力
- 记录功能是否与官方描述一致

**测试 3：输出风格对比**
- 用同一问题分别测试官方 API 和中转站
- 对比回答的详细程度、格式、语气
- 明显差异可能表明模型被替换或降级

**实测案例**（2026-08-12）：
- [平台 A]：Model ID 准确，thinking 功能正常，输出风格与官方一致 ✅
- [平台 D]：声称 Opus 5，但不支持 thinking，疑似降级模型 ⚠️

![模型真实性测试：上下文能力与输出风格对比](../images/articles/choose-02-model-verification.png)

### 第 3 步：真实成本计算

**操作**：
1. 在平台价格页面记录：输入/输出价格、倍率、汇率
2. 设计一个真实任务（例如：总结 3000 字文章）
3. 实际执行任务，记录消耗 token 数
4. 根据账单核对实际扣费

**成本核对清单**：

需要同时考虑的费用项：
- ✓ 输入 token 单价
- ✓ 输出 token 单价
- ✓ 缓存 token 单价（如果使用 Prompt Caching）
- ✓ 图片处理费用（如果使用视觉模型）
- ✓ 工具调用额外费用（如果使用 Function Calling）
- ✓ 线路倍率（如 1.2x、1.5x）
- ✓ 充值汇率（如 ¥7.2/USD）

**计算示例**：

假设任务：用 Claude Opus 5 总结 3000 字文章

官方价格（2026-08）：
- 输入：$15/M tokens（约 4500 tokens）
- 输出：$75/M tokens（约 500 tokens）
- 总成本：(4500×15 + 500×75) / 1,000,000 = $0.105

中转站 A（1.2x 倍率，¥7.2 汇率）：
- 成本：$0.105 × 1.2 × 7.2 = ¥0.907

中转站 B（1.5x 倍率，¥7.0 汇率）：
- 成本：$0.105 × 1.5 × 7.0 = ¥1.103

**实际扣费验证**：
- 在用户中心查看消耗明细
- 对比预估成本和实际扣费
- 如果差异超过 10%，需要询问客服原因

![真实账单截图与扣费明细对比](../images/articles/choose-03-cost-verification.png)

### 第 4 步：稳定性测试

**操作**：
1. 分别在工作日上午、晚间高峰、周末测试
2. 记录每次请求的首字响应时间和完整响应时间
3. 连续发送 10 次请求，统计成功率和错误类型
4. 查看平台是否有状态公告页面

**测试记录表**：

| 时段 | 首字延迟 | 完整响应 | 成功率 | 错误类型 |
|------|---------|---------|--------|---------|
| 工作日 10:00 | - | - | - | - |
| 工作日 20:00 | - | - | - | - |
| 周末 14:00 | - | - | - | - |

**验证标准**：

✅ **稳定平台特征**：
- 首字延迟 < 2 秒
- 完整响应时间稳定（波动 < 30%）
- 成功率 > 95%
- 有清晰的限流说明（如：100 次/分钟）
- 有实时状态页面和故障公告

⚠️ **不稳定信号**：
- 晚间高峰明显变慢或频繁超时
- 返回 502/503 错误但没有公告说明
- 限流规则不明确，被限流后不知道何时恢复

**应用场景匹配**：
- 偶尔聊天：可以容忍晚间略慢，但不能频繁断线
- 自动化任务：必须有稳定的限流规则和重试策略
- 生产环境：需要 SLA 保证和备用线路

![12家平台稳定性实测数据对比](../images/articles/choose-04-stability-test.png)

### 第 5 步：安全控制检查

**操作**：
1. 登录后台，查看密钥管理功能
2. 检查是否支持多密钥和单独限额
3. 查看用量明细的颗粒度（是否精确到每次请求）
4. 阅读隐私政策，确认数据处理方式
5. 测试是否支持登录保护（如 2FA）

**安全功能清单**：

必备功能：
- ✓ 支持创建多个 API Key
- ✓ 每个 Key 可设置独立额度限制
- ✓ 用量明细精确到单次请求
- ✓ 支持一键撤销所有 Key
- ✓ 登录异常通知（如新设备登录）

加分功能：
- ✓ 支持 2FA 或邮箱验证码登录
- ✓ IP 白名单限制
- ✓ 请求日志保留期限可查（如 7 天）
- ✓ 隐私政策明确说明不记录对话内容

**隐私政策检查要点**：

在隐私政策中查找以下信息：
1. 请求内容是否会被记录？记录多久？
2. 是否会用于训练模型或分析用途？
3. 数据存储在哪里？是否加密？
4. 第三方分享政策是什么？

**重要提醒**：
即使隐私政策写得很好，敏感内容（如公司内部数据、个人隐私信息、未发布的创作）仍不应仅依赖一份网页承诺。真正敏感的任务建议使用官方 API。

![密钥管理界面截图与隐私政策对比表](../images/articles/choose-05-security-features.png)

### 第 6 步：售后响应测试

**操作**：
1. 充值前先通过工单或群组提一个具体问题
2. 记录提问时间和首次回复时间
3. 观察回复的专业程度（是否能解决问题，还是只有套话）
4. 查看是否有历史公告记录和故障处理透明度

**测试问题示例**：
- "Claude Opus 5 的倍率是多少？如何计算实际成本？"
- "如果遇到 429 限流错误，应该如何处理？"
- "余额用完后会自动停止服务，还是会透支？"

**验证标准**：

✅ **优质售后特征**：
- 1-4 小时内回复（工作时间）
- 能准确回答计费和技术问题
- 有工单系统留存记录
- 有公开的故障公告和处理进展

⚠️ **风险信号**：
- 24 小时无回复
- 回复只有"请稍等""正在处理"等套话
- 只有群聊，没有工单或邮件留证
- 历史故障处理不透明

**留证重要性**：
在余额争议、扣费异常、服务中断时，工单系统和邮件记录是唯一有效的证据。仅在群聊中沟通很难在事后追溯。

![售后响应时间与专业度评分对比](../images/articles/choose-06-support-quality.png)

### 第 7 步：退出机制评估

**操作**：
1. 在服务条款中查找余额有效期和退款规则
2. 测试客户端更换 Base URL 的难度
3. 确认是否支持数据导出（用量记录、账单明细）
4. 评估迁移到其他平台的成本

**退出机制检查清单**：

**余额和退款**：
- 余额有效期是多久？（如 1 年、永久）
- 是否支持退款？有无手续费？
- 退款需要多久到账？
- 小额余额（如 < ¥5）是否可退？

**数据导出**：
- 能否导出完整的用量明细？
- 能否导出历史账单？
- 数据格式是否标准（如 CSV、JSON）？

**迁移难度**：
- 客户端能否快速更换 Base URL？
- 模型名称映射是否标准（如用 `claude-opus-5` 而非自定义名称）？
- 是否需要修改大量代码？

**实测案例**（2026-08-12）：
- Cherry Studio / Chatbox：更换 Base URL 只需 1 分钟 ✅
- 自定义代码：如果 hardcode 了 URL，需要逐个文件修改 ⚠️

**降低迁移成本的建议**：
- 使用支持快速切换的客户端
- 在代码中使用环境变量存储 Base URL
- 定期备份用量数据到本地

## 结果验证

完成 7 步检查后，你应该得到：

✅ **检查完成标志**：
- 一份完整的对比表格，包含 3-5 家平台的 7 项评分
- 每家平台的小额测试结果（实际成本、响应时间、成功率）
- 至少一次售后沟通记录（回复时间、专业度）

✅ **可以开始长期使用的信号**：
- 信息透明度、安全控制、退出机制至少达到"部分满足"
- 小额测试 3-7 天无重大问题
- 真实成本在预算范围内
- 售后能正常沟通

⚠️ **需要继续观察的信号**：
- 稳定性测试只做了 1-2 次，样本不足
- 隐私政策模糊，但价格有明显优势
- 售后响应慢，但功能和价格都满足需求

## 常见错误

### 错误 1：只看价格不看透明度

**症状**：选了最便宜的服务商，使用一周后遇到问题找不到客服，余额无法退款。

**原因**：价格低可能是牺牲了服务质量和透明度。没有完整主体信息和服务条款的平台，出问题时维权困难。

**解决方法**：
- 把信息透明度作为第一筛选项，先淘汰主体不明、条款不清的平台
- 在剩余平台中再比较价格
- 即使价格贵 20%，选择信息完整的平台也更安全

### 错误 2：不做小额测试直接大额充值

**症状**：充值 100 元后发现服务不稳定或模型被替换，但已经无法退款。

**原因**：跳过了验证环节，直接进入长期使用。

**解决方法**：
- 每家平台先充 5-10 元
- 用真实任务测试 3-7 天
- 观察稳定性、成本、售后响应
- 确认满意后再增加充值金额

### 错误 3：只测试一次就下结论

**症状**：工作日上午测试一次，速度很快，认为平台很稳定。晚间使用时发现频繁超时。

**原因**：稳定性需要在不同时段、不同负载下测试。单次测试无法反映真实情况。

**解决方法**：
- 至少在 3 个不同时段测试（工作日上午/晚间/周末）
- 每次测试连续发送 10 次请求，统计成功率
- 观察 3-7 天，而不是 1-2 小时

### 错误 4：忽略退出机制

**症状**：使用 3 个月后平台突然宣布停止服务，余额无法退款，迁移到其他平台需要修改大量代码。

**原因**：没有提前评估退出难度和余额政策。

**解决方法**：
- 充值前确认退款政策和余额有效期
- 使用支持快速切换的客户端（如 Cherry Studio）
- 定期导出用量数据备份
- 不要在单个平台充值过多（建议 < ¥500）

## 费用说明

**检查阶段成本**：
- 测试 3 家平台，每家充值 10 元：¥30
- 测试期间对话消耗（约 100 次）：¥5-10
- 总计：¥35-40

**长期使用成本**：
- 取决于你的实际用量和选择的平台倍率
- 建议每月预算：轻度使用 ¥50-100，中度使用 ¥200-500

**退款政策**：
- 部分平台支持无手续费退款（需在服务条款中确认）
- 通常要求余额 > ¥10 才能退款
- 退款到账时间：1-7 个工作日

## 安全提醒

1. **测试阶段不要发送敏感信息**：在确认平台隐私政策和安全措施前，不要发送公司内部数据、个人隐私信息、未发布的创作内容。

2. **记录所有检查结果**：用 Excel 或表格记录每个平台的检查结果、测试数据、沟通记录。出现问题时可以作为证据。

3. **分散风险**：不要在单个平台充值过多（建议 < ¥500）。准备 2-3 个备用平台，降低服务中断影响。

4. **定期复查**：平台的服务质量可能变化。每 3-6 个月重新检查一次信息透明度、稳定性和售后响应。

5. **小额试用原则**：即使平台看起来很完美，也要先小额充值测试。不要因为注册优惠或折扣而一次性充值大额。
