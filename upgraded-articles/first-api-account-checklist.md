## 开头

第一次注册 AI API 服务时，90% 的新手会遇到问题：充错平台（钓鱼网站）、充多了无法退款、配置错误无法使用。正确流程分 4 个阶段：注册前验证官网（避免钓鱼）、充值前小额测试（验证可用）、创建密钥设权限（安全防护）、测试后核对账单（确认正确）。本文给出 32 项检查清单和每步的具体操作，帮你避开常见陷阱，2026 年 8 月验证有效。

## 准备工作

在注册前，你需要：

1. **明确需求**  
   - 使用场景：聊天 / 翻译 / 编程
   - 预算：每月 ¥50 / ¥200 / ¥500
   - 模型：GPT-4 / Claude / Gemini

2. **准备材料**  
   - 邮箱（建议专用邮箱）
   - 支付方式（支付宝/微信/信用卡）
   - 密码管理器（如 Bitwarden）

3. **预计时间**  
   完整流程约 30-45 分钟

## 阶段 1：注册前验证（10 项）

### ✅ 1. 确认访问真实官网

**如何验证**：

| 检查项 | 正确 | 错误 |
|--------|------|------|
| 域名 | `openai.com` | `openai-api.com` ❌ |
| HTTPS | ✅ 有绿色锁 | ❌ 不安全警告 |
| 搜索引擎 | 排名第一的自然结果 | 广告位（标"广告"） |

**常见钓鱼手法**：

| 真实网站 | 钓鱼网站 |
|---------|---------|
| `openai.com` | `openai-api.com` |
| `anthropic.com` | `anthropic-ai.com` |
| `claude.ai` | `claude-api.com` |

**验证方法 1：查看域名**

```
✅ 正确：https://platform.openai.com/signup
❌ 钓鱼：https://openai-platform.com/signup
```

**验证方法 2：查看证书**

1. 点击浏览器地址栏的锁图标
2. 查看证书信息
3. 确认颁发给 `openai.com` 等正确域名

**真实案例**（2025-11）：
- 用户搜索"OpenAI API 注册"
- 点击了搜索结果第一位（广告）
- 域名是 `openai-register.com`
- 充值 ¥500 后发现是钓鱼网站
- 损失全部金额，无法追回

### ✅ 2. 记录官网信息

**需要保存**：

| 信息 | 保存方式 | 用途 |
|------|---------|------|
| 官网域名 | 浏览器书签 | 下次直接访问 |
| 公告页 | URL 保存 | 查看维护通知 |
| 客服渠道 | 工单/邮箱/群组 | 遇到问题联系 |
| 用户协议 | 网页另存为 | 维权证据 |

**客服渠道验证**：

```
✅ 有多个渠道：工单系统 + 邮箱 + 官方群
⚠️ 只有 QQ 群：可能不正规
❌ 完全无客服：风险极高
```

### ✅ 3. 查看服务条款关键信息

**必读条款**：

| 条款 | 重点查看 |
|------|---------|
| 余额有效期 | 多久未使用会清零 |
| 退款条件 | 能否退款，如何申请 |
| 发票规则 | 是否提供发票 |
| 故障补偿 | 服务中断如何赔偿 |
| 禁止行为 | 哪些使用会被封号 |

**警告信号**：

| 条款内容 | 风险等级 |
|---------|---------|
| "余额不退款" | 🟡 中等（需小额测试） |
| "不提供任何保证" | 🔴 高（谨慎充值） |
| 完全无服务条款 | 🔴 极高（不建议使用） |

### ✅ 4. 查看运营主体信息

**需要确认**：

- [ ] 公司名称
- [ ] 注册地址
- [ ] 统一社会信用代码
- [ ] 联系电话/邮箱

**查询方法**：

1. 网站底部查看"关于我们"或"公司信息"
2. 用天眼查等工具查询公司
3. 确认公司真实存在且正常营业

**警告**：
- ❌ 完全无运营主体信息
- ❌ 公司信息与服务不匹配（如：卖鞋的公司做 AI API）

### ✅ 5-10. 注册前检查清单

- [ ] 5. 网站有 HTTPS 加密（绿色锁）
- [ ] 6. 有明确的隐私政策
- [ ] 7. 价格表清晰（不是"面议"）
- [ ] 8. 有用户评价或社区（非刷单）
- [ ] 9. 运营时间 ≥3 个月（新平台风险高）
- [ ] 10. 搜索服务商名称，无大量负面评价

## 阶段 2：充值前验证（10 项）

### ✅ 11. 先进入控制台，不要急着充值

**操作顺序**：

```
❌ 错误：注册 → 立即充值 → 发现无法使用 → 无法退款
✅ 正确：注册 → 进控制台 → 查看功能 → 小额测试 → 确认可用 → 充值
```

### ✅ 12. 确认能看到所需功能

**检查清单**：

- [ ] 能看到模型列表（GPT-4、Claude 等）
- [ ] 能看到 API 文档
- [ ] 能看到价格表
- [ ] 能看到用量统计/账单页面
- [ ] 能创建 API Key

**如果无法看到**：

1. 可能需要先充值才能使用（⚠️ 风险）
2. 可能账户需要审核（等待 1-3 天）
3. 可能是功能受限账户（联系客服）

### ✅ 13. 弄清充值余额 vs 赠送余额

**余额类型对比**：

| 类型 | 说明 | 能否退款 |
|------|------|---------|
| 充值余额 | 你实际支付的金额 | 部分平台可以 |
| 赠送余额 | 活动赠送（如充 100 送 20） | 通常不能 |
| 试用余额 | 注册赠送 | 不能 |

**典型条款**：

```
充值 ¥100，赠送 ¥20，共 ¥120

说明：
- 充值余额（¥100）可申请退款
- 赠送余额（¥20）不可退款
- 优先使用赠送余额
```

**警告**：
- 如果充 ¥1000 送 ¥500，平台跑路时你损失 ¥1000
- 不要被大额赠送诱惑

### ✅ 14. 理解价格结构

**价格表示例**（GPT-4 Turbo）：

| 价格类型 | 金额 | 说明 |
|---------|------|------|
| 输入价格 | $10/M tokens | 你发送的内容 |
| 输出价格 | $30/M tokens | 模型返回的内容 |
| 缓存价格 | $2.50/M tokens | 重复内容缓存折扣 |

**常见误区**：

```
❌ 错误：只看"GPT-4: $10/M"
✅ 正确：输入 $10/M，输出 $30/M，实际费用取决于输入输出比例
```

### ✅ 15. 区分不同线路价格

部分平台提供多条线路：

| 线路 | 价格 | 速度 | 稳定性 |
|------|------|------|--------|
| 默认线路 | 1.0× | 中等 | 中等 |
| 加速线路 | 1.2× | 快 | 高 |
| 经济线路 | 0.8× | 慢 | 低 |

**确认**：
- 你看的价格是哪条线路？
- 不同线路如何切换？

### ✅ 16. 第一次只充小额

**推荐金额**：

| 用途 | 充值金额 |
|------|---------|
| 测试可用性 | ¥10 |
| 1 周轻度使用 | ¥20-30 |
| 1 月轻度使用 | ¥50-100 |

**原则**：宁可多次小额充值，不要一次大额充值

**真实案例**（2026-01）：
- 用户看到"充 1000 送 500"
- 一次充值 ¥1000
- 3 天后发现服务质量差，想退款
- 服务商："赠送余额不退，充值余额已使用 ¥50，只能退 ¥950"
- 但平台拒绝退款："已使用不退"
- 损失 ¥1000

### ✅ 17-20. 充值前检查清单

- [ ] 17. 已进入控制台并查看功能
- [ ] 18. 已阅读价格表（输入/输出分开计费）
- [ ] 19. 已阅读退款条款
- [ ] 20. 首次充值 ≤¥20

## 阶段 3：创建 API Key（6 项）

### ✅ 21. 给密钥起有意义的名称

**推荐命名**：

```
✅ 好的命名：
  - chatbox-desktop-2026
  - python-script-data-analysis
  - vscode-copilot-work

❌ 不好的命名：
  - test1
  - 我的密钥
  - key
```

**为什么重要**：
- 多个 Key 时能区分用途
- 某个 Key 泄露时能快速定位
- 查看账单时能知道是哪个应用消耗

### ✅ 22. 设置权限和限额

**推荐配置**：

| 配置项 | 新手推荐值 |
|--------|-----------|
| 允许模型 | 只勾选你需要的（不要全选） |
| 每日限额 | ¥20 |
| 每月限额 | ¥100 |
| 过期时间 | 6 个月后 |

**为什么要限制**：
- 防止 Key 泄露后损失巨大
- 防止误操作（如死循环）
- 定期轮换提高安全性

### ✅ 23. 安全保存 API Key

**保存方式对比**：

| 方式 | 安全性 | 推荐 |
|------|--------|------|
| 密码管理器（1Password/Bitwarden） | ⭐⭐⭐⭐⭐ | ✅ 强烈推荐 |
| 环境变量（.env 文件） | ⭐⭐⭐⭐ | ✅ 推荐 |
| 加密笔记（Obsidian） | ⭐⭐⭐ | ✅ 可接受 |
| 记事本（桌面 key.txt） | ⭐ | ❌ 不推荐 |
| 微信/QQ 收藏 | ⭐ | ❌ 不推荐 |
| 截图保存在相册 | ⭐ | ❌ 不推荐 |

**保存内容**：

```markdown
# H API - ChatBox
- 创建时间：2026-08-15
- API Key：sk-abc123...xyz
- 用途：ChatBox 桌面客户端
- 权限：GPT-4, Claude Sonnet
- 限额：每日 ¥20，每月 ¥100
- 过期时间：2027-02-15
```

### ✅ 24-26. 创建密钥检查清单

- [ ] 24. 密钥名称清晰（能识别用途）
- [ ] 25. 已设置权限限制（不要全选模型）
- [ ] 26. 已设置每日/每月限额

## 阶段 4：首次测试（6 项）

### ✅ 27. 配置客户端

**ChatBox 配置示例**：

```
服务商设置：
  名称：H API
  类型：OpenAI 兼容
  
接口配置：
  Base URL：https://api.h-api.com/v1
  API Key：sk-abc123...xyz
  
模型选择：
  点击"刷新模型列表"
  选择：gpt-4-turbo-2024-04-09
```

### ✅ 28. 发送短测试请求

**第一条测试消息**：

```
你：请只回复：连接成功

预期回复：连接成功
```

**为什么用短消息**：
- Token 少，费用低（约 ¥0.001）
- 快速验证配置正确
- 失败时容易排查

**成功标志**：
- ✅ 1-3 秒内收到回复
- ✅ 回复内容正确
- ✅ 无错误提示

**如果失败**：
- 401 → API Key 错误，重新复制
- 404 → Base URL 错误，检查是否包含 /v1
- model not found → 模型名称错误，用模型列表选择

### ✅ 29. 检查账单记录

**登录控制台查看账单**：

| 检查项 | 预期值 |
|--------|--------|
| 时间 | 刚才发送的时间 |
| 模型 | gpt-4-turbo-2024-04-09 |
| 输入 Tokens | 约 10 |
| 输出 Tokens | 约 5 |
| 费用 | 约 ¥0.001-0.002 |

**警告信号**：

| 现象 | 可能问题 |
|------|---------|
| 账单无记录 | 可能免费试用，或记录延迟 |
| Token 数异常多 | 可能包含了系统提示词 |
| 费用异常高 | 价格倍率过高，检查价格表 |

### ✅ 30. 测试中文输出

**第二条测试消息**：

```
你：用 100 字介绍北京

预期：返回 100 字左右的中文介绍
```

**检查**：
- 中文输出是否正常（无乱码）
- 字数是否符合要求
- 内容是否准确

### ✅ 31. 测试上下文

**第三、四条测试消息**：

```
你：中国的首都是哪里？
AI：北京。

你：那里的人口有多少？
AI：北京人口约 2154 万（截至 2023 年）。
```

**检查**：
- 第二轮是否理解"那里"指北京
- 说明上下文功能正常

### ✅ 32. 测试停止生成

**操作**：
1. 发送："用 1000 字详细介绍北京"
2. 等待 2 秒
3. 点击"停止生成"按钮

**检查**：
- 能否立即停止
- 账单是否只计算已生成的部分

**设置位置**：

**时间节点**：

| 时间 | 任务 |

**备用账号要求**：
- 已注册并充值 ¥10

## 常见错误

### 错误 1：冲动充值大额

**案例**：
- 看到"充 1000 送 500"
- 未测试就充值 ¥1000
- 发现服务质量差
- 无法退款

**正确做法**：
- 先充 ¥10-20 测试
- 使用 1-2 周确认稳定
- 再按月度预算充值

### 错误 2：不保存 API Key

**案例**：
- 创建 Key 后未保存
- 关闭页面后无法再查看
- 只能重新创建

**正确做法**：
- 创建后立即复制
- 粘贴到密码管理器
- 确认保存后再关闭页面

### 错误 3：不设置权限限制

**案例**：
- Key 权限设置为"全部模型"
- Key 泄露后被盗刷
- 1 天消耗 ¥3000

**正确做法**：
- 只开放需要的模型
- 设置每日限额 ¥20-50
- 定期检查账单

### 错误 4：不测试就大量使用

**案例**：
- 充值后直接上传 100 个文件批量处理
- 发现模型不对（套壳）
- 已消耗 ¥500，无法退款

**正确做法**：
- 先发几条短消息测试
- 验证模型真实性
- 核对账单后再批量处理

### 错误 5：忘记准备备用

**案例**：
- 只配置了一家服务商
- 服务商故障，工作完全中断
- 临时注册新账号，耗时 2 小时

**正确做法**：
- 至少准备 2 个独立服务商
- 备用账号已充值 ¥10
- 每月测试一次确认可用
