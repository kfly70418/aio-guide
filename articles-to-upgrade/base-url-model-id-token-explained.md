## Base URL：请求要去的地址

Base URL 是 API 的基础地址。客户端会在它后面组合具体接口路径，再发送请求。不同服务商的地址不同，有的平台要求填写到域名，有的平台要求包含版本路径。应直接复制服务商文档中的示例，不要根据浏览器首页地址自己猜。

多一个斜杠通常问题不大，但漏掉版本路径、把控制台网址当成 API 地址，或混用不同协议，都会导致 404、连接失败或返回网页内容。

## 模型名称：你要调用谁

模型名称也叫 Model ID。它是服务端识别模型的准确代号，不一定等于页面上的中文展示名。字母、数字、短横线和版本后缀都可能有意义。

如果服务商提供“模型列表”按钮，应先刷新列表再选择；必须手填时，从控制台复制。不要仅凭宣传名称推测 Model ID，否则常见结果是“model not found”或无权限。

## Token：计算文字用量的单位

Token 是模型处理文本时使用的切分单位。输入内容、历史对话、系统提示词和模型输出都会占用 Token。一个汉字通常不能简单等同于一个 Token，不同模型的切分方式也可能不同。

费用通常由输入 Token 与输出 Token 分别计算。长文档、保留很多轮历史对话、要求输出很长答案，都会明显增加消耗。

## 三者如何一起工作

客户端把“携带 API Key 的请求”发送到 Base URL，请求中写明模型名称和对话内容。服务端验证密钥、找到模型、统计 Token 并返回结果。也就是说，地址决定去哪里，密钥决定谁在用，模型名称决定用什么，Token 决定处理了多少。

## 配置错误时怎样判断

- 401 或无权限：先检查 API Key。
- 404 或返回网页：先检查 Base URL。
- model not found：检查模型名称和账户权限。
- 余额下降过快：检查输入、输出与历史上下文的 Token。

排查时一次只改一项，并用最短问题复测。这样才能知道是哪项改动真正解决了问题。
