## 先区分故障和停运

短时维护、域名故障、上游限流和真正停止运营的表现可能相似。先查看官方公告、控制台和客服渠道，不要根据群聊中的单条消息立刻判断，也不要继续充值“激活线路”。

## 平时应提前做的八件事

1. 只保留一个月左右的滚动余额。
2. 保存充值订单、账单和服务规则。
3. 每个应用使用独立密钥和清晰名称。
4. 准备另一个完全独立的服务商。
5. 记录通用的 Base URL、Model ID 和切换步骤。
6. 定期导出重要对话与提示词，不只存在平台内。
7. 避免依赖某个平台独有且无法迁移的功能。
8. 每月实际测试一次备用线路。

## 无法访问时怎么处理

先停止自动重试，防止服务恢复后集中产生费用。保存错误页面、公告、余额、订单和客服沟通记录。随后切换到已经测试过的备用服务，更新地址、密钥和模型名称，并用短请求验证。

## 余额还能不能退

能否退款取决于服务条款、支付方式、运营主体和实际状态。通过正式工单提出申请并保存记录；涉及金额较大时，可向支付渠道或当地消费者保护机构咨询。不要向声称能“代追回”的陌生人支付更多费用。

## 原密钥是否还要处理

如果控制台仍可访问，应撤销不再使用的密钥并导出账单。即使平台停止服务，也要从本地程序和配置中删除旧密钥，避免日后域名或系统恢复时被误调用。

真正有效的保护发生在停运之前：减少预付余额、保持数据可导出、使用通用接口并让备用线路处于可用状态。
