## 没有适合所有人的固定金额

API 费用取决于模型、输入输出长度和使用频率。偶尔短问答与每天处理长文档的消耗相差很大，所以第一次充值不应根据别人推荐的金额决定。

## 第一次只覆盖测试

先准备五到十个真实任务，包括短问答、长文总结和一次连续对话。充值只需足够完成这些测试并保留少量余量。确认线路、质量、扣费和售后都正常后，再考虑追加。

## 用一周数据估算

正常使用一周，记录总费用和任务数量。排除刚开始反复调试产生的异常消耗后，以周费用乘四估算月度预算。后续按一个月左右用量滚动充值，通常比一次存半年更灵活。

## 为什么不建议被大额赠送吸引

赠送余额可能不能退款、有有效期、限制模型或随活动规则变化。中转平台还存在停止运营、线路调整和余额迁移困难的风险。折扣节省的是一部分费用，大额预付承担的却是全部余额风险。

## 充值前必须查看

确认现金余额与赠送余额的扣除顺序、退款条件、余额有效期、开票规则、最低充值额，以及平台是否支持消费上限和低余额提醒。保存订单凭证与当时的规则页面。

## 什么时候可以增加金额

已经稳定使用一段时间、账单可核对、平台信息透明，并且充值金额即使暂时无法取回也不会影响生活或经营时，才适合按实际月度消耗增加。

第一次充值的目标是购买验证机会，不是锁定最低折扣。先证明服务适合自己，再扩大使用。
