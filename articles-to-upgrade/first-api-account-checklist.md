## 注册前先保存这些信息

确认你访问的是服务商真正的官网，而不是广告页或相似域名。记录网站域名、公告页、客服渠道和用户协议，尤其要找到余额有效期、退款条件、发票规则与故障补偿说明。页面完全没有运营主体和联系方式时，应降低充值金额。

建议使用专门的邮箱注册，并开启可用的双重验证。密码不要与邮箱、网盘或其他网站重复。

## 充值前不要急着付款

先进入控制台，确认确实能看到所需模型、接口文档和用量账单。弄清充值余额与赠送余额的区别，以及赠送金额是否可以退款。价格表中还要区分输入价格、输出价格、缓存价格和不同线路价格。

第一次只充值能够完成几次测试的小额资金。待稳定使用数天并核对账单后，再按一个月左右的实际消耗补充余额。

## 创建 API Key

给密钥起一个能识别用途的名称，例如“个人电脑-Chatbox”，不要使用“test1”这类日后无法分辨的名称。如果平台支持额度上限、模型权限或 IP 限制，第一次就启用。复制密钥后存入密码管理器，不要发到微信群或截图留在相册中。

## 完成第一次测试

在客户端依次填写 Base URL、API Key 和模型名称。先发送“请只回复：连接成功”这类短请求。成功后检查平台账单是否出现对应记录，模型名称、Token 数和扣费是否合理。

随后再测试一段稍长的中文、连续两轮对话和一次停止生成。这样可以同时验证中文输出、上下文和客户端操作。

## 注册后的收尾工作

保存订单或充值凭证，设置低余额提醒，并在日历中安排一周后复查账单。若试用过程中频繁报错，先停止继续充值，记录时间、模型和报错信息后联系客服。

这套顺序的核心是“先验证，再扩大”。账户能登录不等于线路可用，一次请求成功也不等于长期稳定。
