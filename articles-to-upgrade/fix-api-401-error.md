## 401 和 403 通常表示什么

401 多数表示服务端没有接受你的身份凭证，403 多数表示已经识别身份但没有执行该操作的权限。不同平台实现不完全相同，所以还要结合完整错误文字判断。

## 按这个顺序检查

第一，登录控制台确认账户正常、余额可用，密钥没有被禁用或过期。第二，从控制台重新复制密钥，删除客户端旧值后重新粘贴，避免前后空格和换行。第三，确认 Base URL 与这把密钥属于同一个平台，不能拿甲平台的 Key 请求乙平台地址。

第四，查看密钥是否被限制模型、IP、来源或额度。第五，确认所选模型对当前账户开放，有些模型需要单独申请或使用指定线路。

## 为什么修改密码后仍报错

账户登录密码和 API Key 是两个凭证。修改登录密码不一定影响现有密钥；同样，密钥失效也不代表登录密码有问题。应在 API 密钥页面创建新 Key 进行测试。

## 安全的测试方式

新建一把临时、低额度密钥，在空白对话中发送短文本。如果新密钥成功，旧密钥可能已失效；如果仍失败，再核对地址和权限。测试完成后撤销临时密钥。

## 联系客服要提供什么

提供错误状态码、完整错误信息、发生时间、模型名称、接口地址的域名和密钥末四位。完整 API Key、账户密码和验证码都不应发送给客服。

## 何时怀疑账户被限制

所有新旧密钥都失败、账户有余额、地址正确，并且控制台显示审核或风控提示时，可能需要平台人工处理。此时继续创建大量密钥或频繁重试没有帮助，应提交工单等待确认。
