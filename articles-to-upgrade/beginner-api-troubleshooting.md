## 先停止连续重试

连接失败时反复点击发送，可能触发更严格的限流，也可能让多条请求同时扣费。先保存完整报错、发生时间、客户端名称和模型名称，再开始排查。

## 第一步：确认账户状态

登录服务商控制台，查看余额是否大于零、账户是否被暂停、公告中是否有维护，以及当前模型是否仍可用。能打开官网不代表 API 线路正常，控制台公告和用量记录更有参考价值。

## 第二步：重新核对三项配置

从控制台重新复制 API Key、Base URL 和 Model ID，不要凭记忆手输。检查密钥前后是否有空格，接口地址是否误填成控制台网页，模型名称是否包含正确后缀。

## 第三步：用最短请求测试

新建空白对话，关闭联网、图片、工具调用和长上下文，只发送一句短文字。如果短请求成功，问题多半与附件大小、上下文长度或扩展功能有关；如果仍失败，再继续检查网络与线路。

## 第四步：换一个变量

保持其他设置不变，只换同平台的另一个模型；或保持模型不变，只换另一条线路。一次只改一个变量，才能判断故障来自模型、平台还是客户端。

## 常见状态码方向

- 401/403：密钥、权限或账户状态。
- 404：地址路径或模型名称。
- 429：请求过快、账户限额或上游拥堵。
- 5xx：服务端或上游暂时异常。
- 超时：网络、线路、长输出或客户端等待时间。

## 联系客服时怎样描述

提供发生时间、错误代码、模型名称、请求是否为纯文本、是否所有模型都失败，以及一段隐藏密钥后的报错截图。不要只说“用不了”，也不要把完整 Key 发给任何人。

有顺序地排查，通常十分钟内就能把问题缩小到某一层；即使不能自行解决，客服也能更快定位。
