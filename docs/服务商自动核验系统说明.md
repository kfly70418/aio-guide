# 服务商每日自动核验系统

## 📋 功能说明

每天上午 10:00 自动执行以下任务：
1. ✅ 检查所有服务商网站可访问性
2. ✅ 验证 API 端点是否正常
3. ✅ 更新数据库中的核验时间戳
4. ✅ 生成核验报告并保存
5. ✅ 将报告提交到 Git 仓库

## 🚀 部署步骤

### 1. 创建数据库表

在 Supabase SQL Editor 中执行：

```sql
-- 创建核验日志表
CREATE TABLE IF NOT EXISTS verification_logs (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  checked_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  summary JSONB NOT NULL,
  details JSONB NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_verification_logs_checked_at
ON verification_logs(checked_at DESC);
```

### 2. 配置 GitHub Secrets

在 GitHub 仓库设置中添加：

1. 进入 `Settings` → `Secrets and variables` → `Actions`
2. 添加以下 secrets：
   - `NEXT_PUBLIC_SUPABASE_URL`: Supabase 项目 URL
   - `SUPABASE_SERVICE_ROLE_KEY`: Supabase Service Role Key

### 3. 启用 GitHub Actions

文件已创建在 `.github/workflows/daily-verification.yml`

- 每天 UTC 02:00（北京时间 10:00）自动运行
- 也可以在 GitHub Actions 页面手动触发

### 4. 测试运行

**本地测试：**
```bash
# 安装依赖
npm install

# 设置环境变量
export NEXT_PUBLIC_SUPABASE_URL="你的Supabase URL"
export SUPABASE_SERVICE_ROLE_KEY="你的Service Role Key"

# 运行脚本
npx tsx scripts/daily-provider-verification.ts
```

**手动触发 GitHub Actions：**
1. 进入 GitHub 仓库的 `Actions` 页面
2. 选择 `Daily Provider Verification`
3. 点击 `Run workflow` → `Run workflow`

## 🔍 查看历史数据

### 从数据库查询

```sql
-- 查看最近 7 天的核验统计
SELECT
  checked_at::date as date,
  summary->>'total' as total,
  summary->>'online' as online,
  summary->>'offline' as offline
FROM verification_logs
WHERE checked_at > NOW() - INTERVAL '7 days'
ORDER BY checked_at DESC;

-- 查看某个服务商的历史记录
SELECT
  checked_at,
  detail->>'provider_name' as name,
  detail->>'website_status' as status,
  detail->>'response_time' as response_time
FROM verification_logs,
  jsonb_array_elements(details) as detail
WHERE detail->>'provider_name' = 'LinkAI'
ORDER BY checked_at DESC
LIMIT 30;
```

### 从文件查看

```bash

# 查看最近 7 天的报告
ls -lt logs/verification/ | head -8
```

## 📈 数据分析

### 生成可用性趋势图

```sql
-- 过去 30 天的可用性趋势
SELECT
  checked_at::date as date,
  ROUND((summary->>'online')::numeric / (summary->>'total')::numeric * 100, 2) as availability_percent
FROM verification_logs
WHERE checked_at > NOW() - INTERVAL '30 days'
ORDER BY date;
```

### 找出最不稳定的服务商

```sql
-- 过去 30 天离线次数最多的服务商
SELECT
  detail->>'provider_name' as provider,
  COUNT(*) as offline_count
FROM verification_logs,
  jsonb_array_elements(details) as detail
WHERE
  checked_at > NOW() - INTERVAL '30 days'
  AND detail->>'website_status' = 'offline'
GROUP BY detail->>'provider_name'
ORDER BY offline_count DESC
LIMIT 10;
```

## 🛠️ 故障排查

### 脚本执行失败

1. **检查环境变量**
   ```bash
   echo $NEXT_PUBLIC_SUPABASE_URL
   echo $SUPABASE_SERVICE_ROLE_KEY
   ```

2. **检查网络连接**
   ```bash
   curl -I https://supabase.co
   ```

3. **查看详细日志**
   - GitHub Actions: 进入 Actions 页面查看执行日志
   - 本地: 终端会输出详细信息

### GitHub Actions 未触发

1. 检查 `.github/workflows/daily-verification.yml` 是否在 main 分支
2. 检查仓库的 Actions 是否启用
3. 手动触发测试

### 报告未提交到 Git

1. 检查 Git 配置权限
2. 确认 `logs/verification/` 目录存在
3. 查看 Actions 日志中的错误信息
